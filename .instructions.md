# Workspace Instructions: Anforderungsrahmen für WordPress-Plugin

**Erstellt:** 05.05.2026  
**Basis:** Phasen 1-7 Planungsergebnisse

## Rollenmodell (5 Agenten)

1. **Requirements-Interviewer**: Strukturierte Anforderungs-Interviews
   - Input: Feature-Request oder Delta zu letzter Version
   - Output: Fertige Feature-Spezifikation mit allen Pflichtblöcken
   - Frageblöcke: Zielbild, Regeln, Datenfelder, Fehlerfälle, AC, Nicht-Ziele

2. **Spec-Validator**: Konsistenz- und Vollständigkeitsprüfung
   - Input: Feature-Spezifikation
   - Output: Konfliktbericht, Vollständigkeitscheck, Freigabe-Empfehlung
   - Gate: Alle Blöcke vollständig? AC testbar? Keine Konflikte?

3. **Security-Reviewer**: Security-Sichtprüfung
   - Input: Validierte Spezifikation
   - Output: Security-Checkliste (Pass/Risk-Level)
   - Mindestumfang: API-Key-Handling, Admin-Zugriff, Input-Validierung

4. **Dev-Assistant**: Umsetzungsvorbereitung
   - Input: Vollständig freigegebene Feature-Spezifikation
   - Output: Umsetzungsplan (KEINE Code, nur Architektur-Skizze)
   - Inhalt: Komponenten, Abhängigkeiten, Implementierungs-Reihenfolge

5. **Test-Strategist**: Teststrategie
   - Input: Akzeptanzkriterien
   - Output: Priorisierte Testmatrix (Unit, Integration, E2E, Manual)

## Standard-Workflow

```
Interviewer → Validator → Security → Dev → Test
```

Pro Feature, Reihenfolge: Tabellen → Ergebnisse → Spielpläne

## Freigabeprozess

### Ready-for-Implementation Gate

Ein Feature ist umsetzbar WENN:
- ✓ Alle Akzeptanzkriterien Pass
- ✓ Keine High-Risk-Items offen
- ✓ Security-Check bestanden
- ✓ Restpunkte dokumentiert/priorisiert
- ✓ Technische Umsetzungsschätzung vorhanden

### Freigabe-Bedingungen

- **Instanz:** Product Owner
- **Gültigkeit:** 14 Tage
- **Revalidierung Trigger:** Scope-, API-, Security-, AC-Änderung
- **Freigabe-Einheit:** Einzelfeature (nicht blockweise)
- **Pre-Start Check:** 10-Minuten-Readiness-Check vor Umsetzung

### Ausnahmeprozess

Nur mit explizitem **Owner-Waiver** + Risikoakzeptanz dokumentiert.

### Bei Gate-Fehler

Rückgang in den betroffenen Feature-Deep-Dive-Block (max. 2 Loops, dann Eskalation).

## Pflicht-Evidenz für Freigabe

- [ ] Aktualisierte Feature-Spezifikation (versioniert)
- [ ] Validator-Bericht
- [ ] Security-Checkliste
- [ ] Priorisierte Testmatrix
- [ ] Risiko- und Restpunkte-Liste
